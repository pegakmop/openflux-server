# OpenFlux Control Plane — справочник по API

[English](API.md) | [Русский](API.ru.md)

Здесь описан весь HTTP API, который отдаёт `controlplane` (о том, что это за сервис и как его
запустить — см. [README.ru.md](README.ru.md)). Веб-панель `/admin/` — это тонкий клиент поверх
ровно тех же эндпоинтов `/v1/admin/*`, что описаны ниже: всё, что умеет панель, можно сделать и
через `curl`.

## Базовый адрес

Всё ниже — относительно адреса, по которому доступен `controlplane`: например,
`https://ваш-домен/` после того, как `deploy/install.sh` поставил перед ним Nginx + TLS, либо
`http://127.0.0.1:8080` при обращении напрямую.

## Аутентификация

Есть четыре независимых bearer-токена для четырёх разных ролей. Каждый передаётся одинаково:
заголовком `Authorization: Bearer <token>`.

| Токен          | У кого он есть                                                    | Используется на    | Как получить |
|----------------|--------------------------------------------------------------------|---------------------|--------------|
| Токен админа    | У вас (администратора)                                             | `/v1/admin/*`       | Переменная окружения `CONTROLPLANE_ADMIN_TOKEN`, задаётся один раз при развёртывании |
| Ingest-токен    | У стороннего сервиса, который сам выдаёт свои ключи (бот, магазин) | `/v1/ingest/keys`   | `POST /v1/admin/ingest-tokens` |
| Токен ноды      | У процесса exit-ноды                                               | `/v1/nodes/*`       | `POST /v1/admin/nodes` (или `.../rotate-token`) |
| Токен ключа     | У клиента конечного пользователя                                   | `/v1/resolve`       | `POST /v1/admin/keys` (или `/v1/ingest/keys`) |

Токен админа — это одно статическое значение, сравниваемое за постоянное время; он не хранится в
базе данных и не может быть ни получен обратно, ни обновлён через API (только сменой
`CONTROLPLANE_ADMIN_TOKEN` и перезапуском). Ingest-токены, токены нод и токены ключей генерируются
на сервере и возвращаются вам **ровно один раз**, в момент создания/обновления, а хранятся уже
только в виде хэша — получить значение ранее выданного токена снова невозможно, поэтому сохраняйте
его сразу.

## Соглашения

- Все тела запросов и ответов — JSON (`Content-Type: application/json`).
- Тело запроса с неизвестным полем отклоняется с 400, а не молча игнорирует опечатку.
- При ошибке тело ответа — `{"error": "<сообщение>"}` с кодом 4xx/5xx. У части эндпоинтов, которым
  при успехе нечего вернуть (например, удаление ключа), тело ответа отсутствует — `204 No Content`.
- **Важная особенность именования полей:** три admin-эндпоинта на чтение списка/одного объекта
  (`GET /v1/admin/nodes`, `GET /v1/admin/keys`, `GET /v1/admin/keys/{id}`,
  `GET /v1/admin/ingest-tokens`) сериализуют внутренние Go-структуры напрямую, без `json`-тегов —
  поэтому их поля приходят **с заглавной буквы** (`ID`, `Name`, `MaxKeys`, `Status`, ...). Каждый же
  эндпоинт на *создание* использует отдельный тип ответа с обычным `snake_case`
  (`id`, `name`, `max_keys`, `token`, ...). Это реальная непоследовательность API, а не опечатка в
  документации — ориентируйтесь на формы ниже и не считайте их одинаковыми.

## Здоровье сервиса

### `GET /healthz`

Без авторизации. Используется systemd-юнитом / балансировщиком.

```json
{"status": "ok"}
```

## Admin: ноды

Exit-нода — это один работающий процесс движка OpenFlux (обычно тот же сервер, на котором стоит
сам controlplane, хотя ничто не мешает зарегистрировать ещё и запустить их отдельно — см. раздел
«Заметки о масштабировании» в README.ru.md). У каждой ноды свой bearer-токен и вместимость
`max_keys`; новые ключи автоматически назначаются активной ноде с наибольшим свободным резервом.

### `POST /v1/admin/nodes` — зарегистрировать ноду

```json
// запрос
{"name": "node-eu-1", "max_keys": 500}
```
Если `max_keys` не передан или `<= 0`, используется значение по умолчанию — 500.

```json
// ответ 201
{"id": "5b1e...", "name": "node-eu-1", "max_keys": 500, "token": "of_node_..."}
```
`token` показывается один раз — именно его нужно передать процессу exit-ноды как `--node-token`.

### `GET /v1/admin/nodes` — список нод

```json
// ответ 200 — обратите внимание на заглавные поля (см. особенность выше)
[
  {
    "ID": "5b1e...",
    "Name": "node-eu-1",
    "MaxKeys": 500,
    "Status": "active",
    "LastHeartbeatAt": "2026-09-11T10:00:00Z",
    "CreatedAt": "2026-09-01T12:00:00Z"
  }
]
```
`LastHeartbeatAt` равен `null`, если нода ни разу не вызывала
`POST /v1/nodes/{id}/heartbeat`.

### `POST /v1/admin/nodes/{id}/rotate-token` — обновить токен ноды

Немедленно делает текущий токен ноды недействительным и выдаёт новый.

```json
// ответ 200
{"token": "of_node_..."}
```
`404`, если `{id}` не существует.

## Admin: ключи

Ключ — это токен доступа одного конечного пользователя. Привязан к `transport` (сейчас всегда
`"yandex"`) и `doc_url` (ссылка на Yandex Docs, через которую туннелирует клиент), может иметь
лимит трафика.

### `POST /v1/admin/keys` — создать ключ

```json
// запрос
{
  "label": "user-42",
  "doc_url": "https://docs.yandex.ru/docs/edit?url=...",
  "transport": "yandex",
  "traffic_limit_bytes": 10737418240,
  "owner_ref": "customer-id",
  "expires_at": "2027-01-01T00:00:00Z"
}
```
Обязателен только `doc_url`; `transport` по умолчанию `"yandex"`; `traffic_limit_bytes`,
`owner_ref` и `expires_at` необязательны (без лимита / без владельца / без срока действия).

```json
// ответ 201
{"id": "9c2f...", "token": "of_key_...", "deep_link": "openflux://import?data=eyJuYW1lIj..."}
```
`deep_link` присутствует только когда на сервере настроен `CONTROLPLANE_PUBLIC_URL` — переход по
ней сразу открывает Android-приложение на предзаполненном профиле в режиме «key» (см.
`data/ProfileDeepLink.kt` в openflux-app). Иначе поле просто отсутствует.

### `GET /v1/admin/keys` — список ключей

Необязательный параметр запроса `?owner_ref=<значение>` фильтрует по владельцу.

```json
// ответ 200 — заглавные поля (см. особенность выше)
[
  {
    "ID": "9c2f...",
    "Label": "user-42",
    "Transport": "yandex",
    "DocURL": "https://docs.yandex.ru/docs/edit?url=...",
    "AssignedNodeID": "5b1e...",
    "Enabled": true,
    "TrafficLimitBytes": 10737418240,
    "BytesSentTotal": 1048576,
    "BytesReceivedTotal": 2097152,
    "OwnerRef": "customer-id",
    "ExpiresAt": null,
    "CreatedAt": "2026-09-01T12:00:00Z",
    "UpdatedAt": "2026-09-01T12:00:00Z",
    "LastSeenAt": "2026-09-11T09:55:00Z"
  }
]
```

### `GET /v1/admin/keys/{id}` — получить один ключ

Та же форма, что и один элемент списка выше. `404`, если не существует.

### `PATCH /v1/admin/keys/{id}` — изменить лимит трафика ключа

```json
// запрос — задать лимит или null, чтобы снять его
{"traffic_limit_bytes": 21474836480}
```
```json
// ответ 200
{"status": "updated"}
```

### `POST /v1/admin/keys/{id}/enable` / `.../disable`

```json
// ответ 200
{"enabled": true}
```

### `DELETE /v1/admin/keys/{id}`

`204 No Content` при успехе, `404` — если не существует. Необратимо.

## Admin: ingest-токены

Ingest-токен позволяет внешнему сервису (боту, магазину — всему, что само генерирует ссылки на
Yandex Docs и хочет выдавать под них ключи OpenFlux) создавать ключи через API самостоятельно, без
токена администратора.

### `POST /v1/admin/ingest-tokens` — создать токен

```json
// запрос
{"label": "key-gen-bot", "scope": "keys:write"}
```
`scope` по умолчанию `"keys:write"` — единственный scope, который сейчас проверяет
ingest-эндпоинт.

```json
// ответ 201
{"id": "1a2b...", "label": "key-gen-bot", "scope": "keys:write", "token": "of_ingest_..."}
```

### `GET /v1/admin/ingest-tokens` — список

```json
// ответ 200 — заглавные поля (см. особенность выше)
[
  {"ID": "1a2b...", "Label": "key-gen-bot", "Scope": "keys:write", "Enabled": true, "CreatedAt": "2026-09-01T12:00:00Z"}
]
```

### `POST /v1/admin/ingest-tokens/{id}/enable` / `.../disable`

```json
// ответ 200
{"enabled": true}
```
Эндпоинта удаления ingest-токенов нет — утёкший токен нужно отключить.

## Ingest: создание ключей сторонним сервисом

### `POST /v1/ingest/keys`

Авторизация: `Authorization: Bearer <ingest-токен>` (не токен админа). Принимает как один объект,
так и JSON-массив из максимум 200 штук — для пакетного создания.

```json
// запрос — один ключ
{"label": "user-42", "doc_url": "https://docs.yandex.ru/docs/edit?url=...", "traffic_limit_bytes": 10737418240}
```
`doc_url` обязателен для каждого элемента; `transport` по умолчанию `"yandex"`; `owner_ref`
учитывается для каждого элемента отдельно.

```json
// ответ 201 — одиночный запрос, в ответ один объект
{"id": "9c2f...", "token": "of_key_...", "deep_link": "openflux://import?data=eyJuYW1lIj..."}
```
`deep_link` подчиняется тому же правилу, что и в admin-эндпоинте выше (только при настроенном
`CONTROLPLANE_PUBLIC_URL`). На пакетный (массив) запрос в ответ приходит массив таких же объектов
в том же порядке. `403`, если у токена не scope `keys:write`.

## Node: получение назначенных ключей и отчёт об использовании

Эти эндпоинты вызывает сам процесс exit-ноды, авторизуясь собственным токеном ноды. `{id}` в двух
параметризованных маршрутах ниже также принимает буквальную строку `me` — тогда ноде не нужно
заранее знать свой сгенерированный ID; но если ID передан явно, он должен совпадать с нодой,
которой принадлежит токен (иначе `403`).

### `GET /v1/nodes/keys` — список активных ключей, назначенных этой ноде

```json
// ответ 200
[
  {
    "id": "9c2f...",
    "doc_url": "https://docs.yandex.ru/docs/edit?url=...",
    "transport": "yandex",
    "traffic_limit_bytes": 10737418240,
    "bytes_used_total": 3145728
  }
]
```
В списке — только ключи, которые сейчас включены, не просрочены и не превысили лимит; как только
ключ становится отключённым/превысившим лимит, он просто перестаёт появляться здесь при следующем
опросе ноды.

### `POST /v1/nodes/{id|me}/usage` — отчёт о пакете дельт трафика

```json
// запрос — до 1000 записей
{
  "deltas": [
    {"key_id": "9c2f...", "bytes_sent_delta": 1048576, "bytes_received_delta": 2097152}
  ]
}
```
Дельты складываются (это не абсолютные значения) — отчитывайтесь о том, что утекло с прошлого
вызова. Записи с пустым `key_id` тихо пропускаются.

```json
// ответ 200
{"disabled_now": ["9c2f..."]}
```
`disabled_now` — список ID ключей, которые именно в результате этого отчёта превысили лимит
трафика и были автоматически отключены.

### `POST /v1/nodes/{id|me}/heartbeat`

Без тела запроса.

```json
// ответ 200
{"status": "ok"}
```
Обновляет `LastHeartbeatAt` ноды (см. `GET /v1/admin/nodes`) — сегодня это единственное, на чём
основано поле `Status`/панель, чтобы судить о том, жива ли нода.

## Клиент: резолв ключа

### `POST /v1/resolve`

Авторизация: `Authorization: Bearer <токен ключа>`. Ограничен по частоте на IP-адрес источника
(`CONTROLPLANE_RATE_LIMIT_RPS`, по умолчанию 1 запрос/сек, небольшой всплеск) — это единственный
эндпоинт, к которому недоверенный клиентский токен обращается напрямую.

```json
// ответ 200 — активный ключ
{
  "status": "active",
  "doc_url": "https://docs.yandex.ru/docs/edit?url=...",
  "transport": "yandex",
  "bytes_used_total": 3145728,
  "traffic_limit_bytes": 10737418240
}
```
`status` — одно из `active`, `disabled`, `over_quota` или `not_found` (неизвестный/неверный токен
— возвращается как `200`, а не `401`, чтобы клиент не мог по коду ответа отличить «неверный токен»
от «отозванный токен»). `doc_url`/`transport` присутствуют только при `status: "active"`.

## Веб-панель администратора

### `GET /admin/` или `GET /admin/index.html`

Сам GET без авторизации — отдаёт статичную самодостаточную HTML-страницу
(`internal/api/web/admin.html`, встроена в бинарник), которая уже сама на своём экране входа
спрашивает токен администратора и хранит его в `localStorage` браузера, используя как заголовок
`Authorization` для каждого дальнейшего вызова `/v1/admin/*`. Это тонкий клиент ровно поверх этого
API: вкладка «Ключи» (создание/список/фильтр/включение/отключение/удаление) и вкладка «Настройки»
с единственной нодой, зарегистрированной на этом сервере (статус, активность, обновление токена),
плюс управление ingest-токенами — всё на русском, ничего сверх этого.
